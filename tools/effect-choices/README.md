# 選択肢の候補表の生成器

`crates/plugin/data/effect_item_facets.json` を、起動中の AviUtl2 への書き込み
検証で起こす。plugin はこの JSON を `include_str!` でバイナリへ取り込む。

生成器はワークスペースの外にある。`Cargo.toml` の `members` は `crates/*` だけを
指すため、**このディレクトリは製品のビルドにも lint にも関与しない。** 新しい版の
AviUtl2 が出たときに 1 度走らせ、出力をコミットする。

## 前提

- **AviUtl2 が起動していること。** MCP plugin が読み込まれた状態で 1 つだけ立てる。
- **捨てて良いプロジェクトが開いていること。** 生成器はスクラッチのオブジェクトを
  20 数個作り、選択肢を総当たりで書き込む。**既存のオブジェクトには触れないが、
  プロジェクトは編集済みになる。** 保存しないこと。
- **`target/release` か `target/debug` に `aviutl2-mcp-server.exe` があること。**
  release を先に探す。
- **`[Effect]` 節を持つ言語ファイルがあること。** 候補の在庫の供給源である。作者が
  配布する英語言語ファイルがこれにあたる。既定では開発用ディレクトリの
  `data\Language`、次に `%ProgramData%\aviutl2\Language` を見て、`[Effect]` 節を
  持つ最初の `*.aul2` を採る。
- **Node.js。** 標準ライブラリだけで動く。依存パッケージは無い。

## 使い方

```
node tools/effect-choices/generate.mjs
```

| 引数 | 既定 | 内容 |
|---|---|---|
| `--language <path>` | 開発用ディレクトリ → `%ProgramData%` の走査 | 在庫を読む言語ファイル |
| `--out <path>` | `crates/plugin/data/effect_item_facets.json` | 書き出し先 |
| `--server <path>` | `target/release` → `target/debug` | MCP サーバーの実行ファイル |
| `--max-writes <n>` | 50000 | 書き込みの総回数の上限 |

## 何をしているか

言語ファイルの `[Effect]` 節には効果名・項目名・選択肢ラベルが**重複排除された
まま平坦に**並ぶ。どれが選択肢かも、どの項目のものかも書かれていない。そこで
**書き込みの成否そのものを判定に使う**——選択肢に無い値を書くと
`unsupported_operation` / `item_value_not_applied` で失敗し、**状態は変わらない。**

1. 全種別の効果を列挙し、`select` の設定項目を集める
2. 各効果を載せたオブジェクトの作り方を実機で決める。効果から直接作れないものは、
   他の効果から作ったオブジェクトに同伴するかを見る（`テキスト` のオブジェクトには
   `標準描画` が、`フレームバッファ` には `基本出力` が付いてくる）
3. 現在値を在庫の中に見つけ、そこから上下へ 1 件ずつ広げる
4. 1 段目で見つからなかったラベルを、項目ごとに残らず試す
5. スクラッチのオブジェクトを削除する

**対象は `select` だけである。** `combo` は一覧に無い文字列も受理するため書き込み
検証で集合を確定できず、`mask` と `figure` の候補はデータディレクトリの内容に
由来して環境ごとに変わる。

## 出力の読み方

- 効果名と項目名は昇順に並ぶ。差分が読めるようにするためである
- 候補の並びは**在庫の並び順**を保つ。ソートしない
- **在庫から重複排除で消えたラベルの位置は正しくない。** 他の効果名や項目名と綴りが
  同じラベル（`合成モード` の `輝度` など）は在庫では選択肢の帯の外に 1 度だけ現れ、
  その位置に並ぶ。ホストの並びとは違う
- **在庫が覆っていない項目は表に入らない。** 現在値以外を 1 つも確認できなかった
  項目は、実行の最後に理由付きで一覧する。プラグインが提供する効果はここへ落ちる
  ——その候補はプラグイン作者がサイドカーで配る
