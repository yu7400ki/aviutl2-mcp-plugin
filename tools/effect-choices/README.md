# 設定項目の面の生成器

`crates/plugin/data/effect_item_facets.json` を、起動中の AviUtl2 への書き込み
検証で起こす。plugin はこの JSON を `include_str!` でバイナリへ取り込む。

**面**とは、設定項目 1 件について表が述べることである。いまは 2 つある。

| 面 | 内容 | 対象の種別 |
|---|---|---|
| `choices` | 選択肢の候補 | `select` |
| `range` | 値域（`min` / `max`）と小数桁（`decimals`） | `integer` / `number` |

**どちらも SDK からは取れない。** 設定項目の列挙がコールバックへ渡すのは名前と
種別だけであり、選択肢を返す関数も値域を返す関数もヘッダーに存在しない。ホストは
持っているが我々へ渡す口が無いため、**書き込みの成否と、ホストが倒した値そのものを
判定に使う。**

生成器はワークスペースの外にある。`Cargo.toml` の `members` は `crates/*` だけを
指すため、**このディレクトリは製品のビルドにも lint にも関与しない。** 新しい版の
AviUtl2 が出たときに 1 度走らせ、出力をコミットする。

## 前提

- **AviUtl2 が起動していること。** MCP plugin が読み込まれた状態で 1 つだけ立てる。
- **捨てて良いプロジェクトが開いていること。** 生成器はスクラッチのオブジェクトを
  20 数個作り、候補を総当たりで書き込み、値域を探る値で叩く。**既存のオブジェクトには
  触れないが、プロジェクトは編集済みになる。** 保存しないこと。
- **`target/release` か `target/debug` に `aviutl2-mcp-server.exe` があること。**
  release を先に探す。
- **`[Effect]` 節を持つ言語ファイルがあること。** 候補の在庫の供給源である。作者が
  配布する英語言語ファイルがこれにあたる。既定では開発用ディレクトリの
  `data\Language`、次に `%ProgramData%\aviutl2\Language` を見て、`[Effect]` 節を
  持つ最初の `*.aul2` を採る。
- **Node.js。** 標準ライブラリだけで動く。依存パッケージは無い。

## 使い方

```
node tools/effect-choices/generate.mjs
```

| 引数 | 既定 | 内容 |
|---|---|---|
| `--language <path>` | 開発用ディレクトリ → `%ProgramData%` の走査 | 在庫を読む言語ファイル |
| `--out <path>` | `crates/plugin/data/effect_item_facets.json` | 書き出し先 |
| `--server <path>` | `target/release` → `target/debug` | MCP サーバーの実行ファイル |
| `--max-writes <n>` | 60000 | 書き込みの総回数の上限 |

## 候補をどう起こすか

言語ファイルの `[Effect]` 節には効果名・項目名・選択肢ラベルが**重複排除された
まま平坦に**並ぶ。どれが選択肢かも、どの項目のものかも書かれていない。そこで
**書き込みの成否そのものを判定に使う**——選択肢に無い値を書くと
`item_value_not_applied` で失敗し、**状態は変わらない。**

1. 全種別の効果を列挙し、対象の設定項目を集める
2. 各効果を載せたオブジェクトの作り方を実機で決める。効果から直接作れないものは、
   他の効果から作ったオブジェクトに同伴するかを見る（`テキスト` のオブジェクトには
   `標準描画` が、`フレームバッファ` には `基本出力` が付いてくる）
3. 現在値を在庫の中に見つけ、そこから上下へ 1 件ずつ広げる
4. 1 段目で見つからなかったラベルを、項目ごとに残らず試す
5. スクラッチのオブジェクトを削除する

**対象は `select` だけである。** `combo` は一覧に無い文字列も受理するため書き込み
検証で集合を確定できず、`mask` と `figure` の候補はデータディレクトリの内容に
由来して環境ごとに変わる。

## 値域をどう起こすか

**書き戻し照合がそのまま測定器になる。** ホストは値域を外れた値を端へ倒し、桁の
多い小数を項目の桁へ丸める。倒された値は書き込みの失敗の応答に
`observed_value` として載るため、**倒された値そのものが値域である。**

| 探り | 得られるもの |
|---|---|
| 極端に大きい値（10 億） | 上限 |
| 極端に小さい値（-10 億） | 下限 |
| 小数を多く持つ値（`0.123456789`） | 小数桁 |

探りの値は種別ごとに決めてある。`integer` はホスト側の整数の幅に縛られる——
SDK のヘッダーは幅を述べておらず、`i64` の両端を書くと収まらない可能性がある。
10 億は 32 ビット整数の上限の半分以下であり、設定項目が取り得る大きさ（`サイズ` の
上限が 4000、座標が数万）より 5 桁大きい。`number` は倍精度であるためこの縛りを
受けないが、**極端な値をホストが解釈できるかは測っていないため、まず収まる範囲で
試す。**

小数桁の探りは `number` にだけ掛ける。**整数の項目へは小数を持つ値を書く形が
無い。**

## 出力の読み方

- 効果名と項目名は昇順に並ぶ。差分が読めるようにするためである
- 葉は面の組である。**軸（効果名・項目名）と内容（`choices` / `range`）で階層が
  分かれる**ため、面が増えてもトップレベルのキーは増えない
- 候補の並びは**在庫の並び順**を保つ。ソートしない
- **在庫から重複排除で消えたラベルの位置は正しくない。** 他の効果名や項目名と綴りが
  同じラベル（`合成モード` の `輝度` など）は在庫では選択肢の帯の外に 1 度だけ現れ、
  その位置に並ぶ。ホストの並びとは違う
- **値域は測れた欄だけを持つ。** 探りの値が値域の内側へ収まった側は測れない——
  受理されたことが言うのは「端が探りの外にある」ことだけであり、端が無いことの
  証明にはならない。上限だけを測れた項目は `max` だけを持つ
- **覆えなかった項目は表に入らない。** 実行の最後に理由付きで一覧する
  - 候補: 現在値以外を 1 つも確認できなかった項目。プラグインが提供する効果はここへ
    落ちる——その候補はプラグイン作者がサイドカーで配る
  - 値域: 上限も下限も小数桁も測れなかった項目と、探りが `item_value_not_applied`
    以外で失敗した項目。移動を持つ項目（`track_movement_present`）が後者である。
    **黙って値域を持たない項目にはしない**

## 実機なしで確かめられること

生成器はテストを持たない。そのぶん、**表を組み立てる部分は実機を要さない純粋な
関数として切り出し、モジュールとして読み込めるようにしてある。**
`buildDocument` / `inInventoryOrder` / `rangeFacet` / `fractionDigits` /
`observedNumber` は `import` して小さな入力から呼べる。走査が始まるのは
`generate.mjs` を直接実行したときだけである。
