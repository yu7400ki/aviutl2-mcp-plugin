# AviUtl2 を編集する

**この文書は個々の tool が何をするかを述べない。** どの tool が何をし、どの引数に何を書き、どの条件で失敗するかは、tool 定義と入力 schema が正本である。ここへ写せば同じ事実の正本が 2 つになり、片方だけが古くなる。tool 1 個の使い方を知りたいときは、その tool 定義と入力 schema を読む。

ここに在るのは 3 つだけである——**複数の tool にまたがる規約**、**参照文書への導線**、**書ける値を引く経路**。

書いてあるのは実測した事実だけである。確かめていないことは書かない。確かめていないと分かっていることは、そう名乗って書く。

## まず対象を決める

AviUtl2 は同時に複数起動でき、それぞれが別のプロジェクトを開いている。どの要求もどのインスタンスに対するものかを instance_id で指すため、これが決まらないと 1 つも送れない。

instance_id は list_instances が返す。作業を始める前に 1 度呼び、以後は同じ値を使い回す。instance_id を要らないのは list_instances だけである。

## 番号は 0 始まりである

AviUtl2 の UI はレイヤーとフレームを 1 始まりで表示する。tool が受け渡すのは 0 始まりの番号であり、画面で見た番号より 1 小さい。

利用者が画面を見ながら「レイヤー 3 に置いて」と言ったとき、送る値は 2 である。ここを取り違えると、要求は成功したまま別の場所へ書かれる。

レイヤー番号の大小が描画の前後関係を決める規則は [references/layers.md](references/layers.md) にある。**取り違えてもエラーは出ない。**

## selector と世代

selector は自分で組み立てない。読み取りの応答が返した値をそのまま編集へ渡し、編集の応答が返した値をそのまま次の編集へ渡す。

プロジェクト境界の照合材料は selector が運ぶ project_epoch である。selector を持たない tool（create_object・set_layer_state・set_selection・set_grid_bpm・set_scene_settings）だけが expected_project_epoch を要求し、そちらは省略できない。

要求は project_revision を運ばない。読み取りから編集までに revision が進んでいても拒否されない。拒否を避けるために revision を取り直す必要は無い。

## 取り消しの単位

編集 tool の呼び出し 1 回が 1 つの取り消し単位になる。まとめて 1 単位にしたいときは apply_batch を選ぶ。

利用者が 1 回の Undo で戻したいと考えるまとまりを、1 回の呼び出しへ寄せる。逆に、途中まで残ってよい作業を apply_batch へ入れると、最後の 1 件の失敗で全部が巻き戻る。

一般則には例外が 2 つある。

- **set_selection は取り消し単位を作らない。** 実行後に取り消すと、その前に行った編集が取り消される。
- **set_scene_settings は取り消せない。** こちらも取り消しはその前の編集へ飛ぶ。

**create_object_section・delete_object_section・move_object_section・set_grid_bpm の 4 つは、取り消し単位を作るかを確かめていない。** 一般則に含めても例外に数えてもいない。1 回の Undo で戻ることを前提にした手順を、この 4 つの上に組み立てない。

## 失敗したときにすること

**失敗したら、同じ要求をそのまま送り直さない。** 失敗の text content には details のキーと値が並ぶ。読んで、次の要求を組み立て直す。

並ぶのは全件とは限らない。**上限を超えた分は行の単位で省かれ、省いたことは text に出る。** 伏せ字の対象になるキーは値が出ない。省かれたと書いてあるときは structuredContent を見る。

対象が変化していた precondition_failed では details.current_object に対象の現在の姿が入り、そのまま次の要求の selector にできる。apply_batch だけは何番目で落ちたかを併せて示すため details.failed_object という別のキーで返す。

書き込みを発行した後に落ちた失敗には details.mutation_issued が true で付く。付かない失敗は 1 バイトも書いていないため、対象を読み直さずに要求を直して送り直せる。

timeout は変更が無かったことを意味しない。details.change_applied が "no" なら未適用のため再送してよく、"unknown" なら読み直して確認してから再送する。

## 使える効果と書ける値を引く

**使う効果を、思い付いた分だけに絞らない。** インスタンスが持つ効果の一覧は list_available_effects が返す。実測では、一覧に出ていたフィルタ効果 97 件が**1 つも候補に上がらなかった**——名前は見えていたが、何をするものか分からず、検討そのものが起きなかった。

**この取りこぼしはエラーを出さない。** 使わなかったことは応答にも失敗にも現れず、成果物が地味なまま終わるだけである。組み立てを始める前に一覧を引き、目に留まったものを開く。

効果の名前もここには写していない。**知らないものは思い付けない。**思い付いた名前を確かめるためではなく、**何が在るかを知るために**一覧を引く。

設定項目に何を書けるか分からないときは describe_effects を呼ぶ。choices が候補を、range が値域と小数桁を返す。どちらも null の項目は表に載っていないだけであり、既存オブジェクトの値を get_object で読んで倣う。フォント名は list_fonts が返す。

**候補の値そのものはここに写していない。** 正本は describe_effects が返す表であり、写せば正本が 2 つになって、片方だけが古くなる。合成モードにも文字装飾にも図形の種類にも候補は在る——ここに並んでいないことは、無いことを意味しない。

値域を引くのは、外れたときに失敗するからだけではない。**値域の内側での取り違えは失敗しない。** 縦横比に -96 と書くつもりで -0.96 と書けば、有効な値であるため書き込みは通り、描画して初めて分かる。
