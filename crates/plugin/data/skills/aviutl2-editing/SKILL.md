# AviUtl2 を編集する

**この文書は個々の tool が何をするかを述べない。** どの tool が何をし、どの引数に何を書き、どの条件で失敗するかは、tool 定義と入力 schema が正本である。ここへ写せば同じ事実の正本が 2 つになり、片方だけが古くなる。

## まず対象を決める

AviUtl2 は同時に複数起動でき、それぞれが別のプロジェクトを開いている。どの要求もどのインスタンスに対するものかを instance_id で指すため、これが決まらないと 1 つも送れない。

instance_id は list_instances が返す。作業を始める前に 1 度呼び、以後は同じ値を使い回す。instance_id を要らないのは list_instances だけである。

**インスタンスだけでは宛先が決まらない。** 1 つのプロジェクトは複数のシーンを持ち、読み書きが届くのは AviUtl2 が今開いているシーンだけである。要求は scene_id または expected_scene_id で「どのシーンのつもりか」を名乗り、現在シーンが違えば拒否される。

**シーンを切り替える経路は無い。** 別のシーンへ手を入れる必要が出たら、利用者に AviUtl2 側で切り替えてもらう。レイヤー番号もフレーム番号もシーンごとに別のものを指すため、切り替わった後に古い番号を送っても通らない。

## 番号は 0 始まりである

AviUtl2 の UI はレイヤーとフレームを 1 始まりで表示する。tool が受け渡すのは 0 始まりの番号であり、画面で見た番号より 1 小さい。

利用者が画面を見ながら「レイヤー 3 に置いて」と言ったとき、送る値は 2 である。ここを取り違えると、要求は成功したまま別の場所へ書かれる。

レイヤー番号の大小が描画の前後関係を決める規則は [references/layers.md](references/layers.md) にある。**取り違えてもエラーは出ない。**

## selector と世代

selector は自分で組み立てない。読み取りの応答が返した値をそのまま編集へ渡し、編集の応答が返した値をそのまま次の編集へ渡す。

プロジェクト境界の照合材料は selector が運ぶ project_epoch である。要求が selector を 1 つも運ばないことがある tool（create_object・set_layer_state・set_selection・set_grid_bpm・set_scene_settings）だけが expected_project_epoch を要求し、そちらは省略できない。

編集の要求は project_revision を運ばない。読み取りから編集までに revision が進んでいても拒否されない。拒否を避けるために revision を取り直す必要は無い。

**一覧の続きを引く要求だけは運ぶ。** 先頭ページが返した値をそのまま送り返す欄である。**照合するのはシーンの中身を並べる 3 つ（list_objects・list_layers・get_selection）だけであり、間に編集が挟まると拒否される。**

**残りの一覧は受け取っても照合しない。** 続きを引く間に中身が変われば、拒否されないまま取りこぼす。

**拒否されたら先頭のページから引き直す。** 取り直すのは revision ではなく一覧である。

## 取り消しの単位

変更が起きた編集 tool の呼び出し 1 回が、1 つの取り消し単位になる。まとめて 1 単位にしたいときは apply_batch を選ぶ。

利用者が 1 回の Undo で戻したいと考えるまとまりを、1 回の呼び出しへ寄せる。逆に、途中まで残ってよい作業を apply_batch へ入れると、最後の 1 件の失敗で全部が巻き戻る。

一般則には例外が 3 つある。**いずれも、実行した後の 1 回の Undo はその前の編集へ飛ぶ。**

- **set_selection は取り消し単位を作らない。** 実行後に取り消すと、その前に行った編集が取り消される。
- **set_grid_bpm も取り消し単位を作らない。** 置き換える前の一覧は Undo では戻らない。戻せるようにしておきたいなら、読み取った一覧を自分で保持する。
- **set_scene_settings は取り消せない。** こちらも取り消しはその前の編集へ飛ぶ。

## 失敗したときにすること

**失敗したら、同じ要求をそのまま送り直さない。** 失敗の text content には details のキーと値が並ぶ。読んで、次の要求を組み立て直す。

並ぶのは全件とは限らない。**行の単位で省かれた分は text にだけ欠け、省いたことは text に出る**——省かれた行は structuredContent で読める。**配列の要素は text と structuredContent の両方から同じだけ落ち、structuredContent を見ても戻らない**——落とした位置と切る前の件数は details.truncated が名乗る。**名乗るのはこの 2 つだけであり、それ以外の切り詰めは名乗られない。** 伏せ字の対象になるキーは値が出ない。

**次に何をするかは details.retry_requires が名乗る。** 編集が AviUtl2 へ届いて落ちたときは必ず付き、値は 3 つしかない——`resend` はそのまま送り直してよい、`refetch` は対象を読み直して要求を作り直す、`none` は何度送っても解消しない。**`none` を握ったまま繰り返すのが、最も長く空回りする経路である。** 別の要求で前提そのものを変えるか、利用者へ返す。

編集の失敗がこのキーを持たないなら、要求はそこまで届いていない——引数の検証か、インスタンスへの到達で落ちている。読み直しても変わらない。直すのは要求の形である。

**何が食い違ったかは details.mismatch が名乗る。** 編集が返す precondition_failed に付き、読み直す先がこれで変わる。

- `fingerprint`——対象そのものが変わった。読み直すのはその 1 件でよい
- `scene_id`——現在シーンが別のシーンへ移った。番号で指したものは全て別のものを指しており、シーンから取り直す
- `project_epoch` を名に含む値——開いているプロジェクトが別物になった。読み取りの最初からやり直す

対象が変化していた precondition_failed では details.current_object に対象の現在の姿が入り、そのまま次の要求の selector にできる。apply_batch だけは何番目で落ちたかを併せて示すため details.failed_object という別のキーで返す。

書き込みを発行した後に落ちた失敗には details.mutation_issued が true で付く。付かない失敗は 1 バイトも書いていないため、対象を読み直さずに要求を直して送り直せる。付く失敗が読み直しを要するかは details.retry_requires が名乗る——発行した変更が戻っていれば読み直す先は無い。

timeout は変更が無かったことを意味しない。details.change_applied が "no" なら未適用のため再送してよく、"unknown" なら読み直して確認してから再送する。

**プレビュー再生中とファイル出力中は、読み取りも編集も通らない。** edit_blocked が返り、details.edit_state がどちらであるかを名乗る。**フレームの描画はこれと別の系統であり、どちらで止まるかは render_frame の説明が述べる。**

**起動処理中・終了処理中と、編集ハンドルの準備待ちでは host_busy が返る。** AviUtl2 を起動した直後に踏みやすい。

**details.retry_after_ms を持つ失敗は、要求を作り直さずその時間だけ待って送り直す。** 待てば必ず解けるわけではない——終了処理に入っていたインスタンスは、待った先で instance_stale になる。そこで初めてインスタンスを探し直す。

## 使える効果と書ける値を引く

**使う効果を、思い付いた分だけに絞らない。** インスタンスが持つ効果の一覧は list_available_effects が返す。思い付いた名前を確かめるためではなく、**何が在るかを知るために**、組み立てを始める前に一覧を引き、目に留まったものを開く。

**取りこぼしはエラーを出さない。** 使わなかった効果は応答にも失敗にも現れず、成果物が地味なまま終わるだけである。

設定項目に何を書けるか分からないときは describe_effects を呼ぶ。choices が候補を、range が値域と小数桁を返す。どちらも null の項目は表に載っていないだけであり、既存オブジェクトの値を get_object で読んで倣う。フォント名は list_fonts が返す。

**候補の値そのものはここに写していない。正本は describe_effects が返す表である。** 合成モードにも文字装飾にも図形の種類にも候補は在る——ここに並んでいないことは、無いことを意味しない。

値域を引くのは、外れたときに失敗するからだけではない。**値域の内側での取り違えは失敗しない。** 縦横比に -96 と書くつもりで -0.96 と書けば、有効な値であるため書き込みは通り、描画して初めて分かる。
