# object alias の書式

オブジェクトの生テキスト表現である。AviUtl2 がエイリアスファイルとプロジェクトファイルへ書くのと同じ形式であり、`create_object` の `object_alias` へ渡せる。

**この文法は応答から得られない。** 読み取りは alias の生文字列を返すが、その文字列がどう構成されているかを述べる欄はどこにも無い。

## なぜ使うか

実測: effect 2 個とトラックバー 2 本を持つオブジェクトを alias で 1 回作り、読み直したところ **1 バイト違わず同じ alias が返った。** 同じものを設定項目ごとに書いて組むと 10 往復になり、**alias なら 8 分の 1 以下で済む。**

中身が最初から決まっているオブジェクトは alias で作る。作った後に 1 項目だけ直す場合は、設定項目を書く経路のほうが短い。

## 構造

```
[Object]
frame=0,80
[Object.0]
effect.name=図形
サイズ=600
[Object.1]
effect.name=標準描画
X=-600.00,600.00,直線移動,0
透明度=100.00,0.00,直線移動,0
```

- `[Object]` がオブジェクト 1 個。`[Object.<n>]` が n 番目の effect で、0 から始まる。
- `effect.name=` が effect の名前。エフェクト一覧が返す名前をそのまま書く。
- 残りの行が `<項目名>=<値>` である。項目名は設定項目の名前そのものである。

## 複数のオブジェクトを持つ形

1 つの alias は複数のオブジェクトを持てる。そのとき節の名前は `[Object]` ではなく 0 から始まる番号になり、各オブジェクトが `layer=` を持つ。

```
[0]
layer=0
frame=0,80
[0.0]
effect.name=テキスト
[1]
layer=1
frame=0,80
[1.0]
effect.name=図形
```

**`layer` は絶対番号ではなく、配置先を起点とする相対値である。** 実測: この形の alias を作成すると、配置先のレイヤーと、その次の番号のレイヤーへ 1 つずつ生まれた。配置先を 1 つ指定すれば、残りはそこからの相対で決まる。

## frame 行が区間を決める

```
frame=<開始>,<中間点…>,<終了>
```

中間点の位置はここに入る。`frame=0,40,80` なら中間点が 1 個あり、区間は 2 つになる。

## トラックバーの値と移動

```
<項目名>=<値0>,…,<値N>,<移動モード名>,<フラグ>
```

- **値の個数は `frame=` の要素数と一致する。** 中間点 2 個 → 3 区間 → 値 4 個である。
- `<移動モード名>` は AviUtl2 が持つ移動方法の名前である。
- `<フラグ>` は整数 1 個で、ビットの意味は **bit0 加速 / bit1 減速 / bit2 中間点無視 / bit3 時間制御** である。実測: `,5`（bit0 と bit2）で作って読み直すと、加速が真・減速が偽・中間点無視が真・時間制御が偽になった。

プロジェクトファイルから採った実例。

```
frame=637,638,651,652
音量=0.00,100.00,100.00,0.00,直線移動,0
再生位置=0.000,0.920,再生範囲,0
```

移動を持たない項目は値 1 個だけを書き、移動モード名もフラグも付けない。

## 黙って捨てられる書き方がある

**移動モード名が不正な場合と、末尾のフラグを欠いた場合、その行ごと黙って破棄されて既定値になる。** エラーも警告も返らない。alias が受理されたことは、書いた行が全て効いたことを意味しない。

alias で作った後は読み直して、書いたとおりになっているかを確かめる。1 バイト違わず返るため、比較はそのまま文字列で行える。

## トラックバーグループ

`Group=1` / `Group2=1` / `Group3=1` の行がトラックバーのグループ区切りである。以降の項目が同じグループに属する。

## 未確認

**移動モードがパラメータを取る場合の並びは確かめていない。** 実測したのはパラメータを取らない移動モードだけである。パラメータ付きの移動を alias で書く必要が出たら、既存オブジェクトの alias を読んで並びを写す。
