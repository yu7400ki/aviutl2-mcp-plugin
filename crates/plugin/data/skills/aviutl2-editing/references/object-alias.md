# object alias の書式

オブジェクトの生テキスト表現である。AviUtl2 がエイリアスファイルとプロジェクトファイルへ書くのと同じ形式であり、`create_object` の `object_alias` へ渡せる。

読み取りは alias の生文字列を返すが、その文字列がどう構成されているかを述べる欄はどこにも無い。

## なぜ使うか

実測: effect 2 個とトラックバー 2 本を持つオブジェクトを alias で 1 回作り、読み直したところ **1 バイト違わず同じ alias が返った。** 同じものを設定項目ごとに書いて組むと 10 往復になり、**alias なら 8 分の 1 以下で済む。**

中身が最初から決まっているオブジェクトは alias で作る。作った後に 1 項目だけ直す場合は、設定項目を書く経路のほうが短い。

## 構造

```
[Object]
frame=0,80
[Object.0]
effect.name=図形
サイズ=600
[Object.1]
effect.name=標準描画
X=-600.00,600.00,直線移動,0
透明度=100.00,0.00,直線移動,0
```

- `[Object]` がオブジェクト 1 個。**`[Object.<n>]` は effect を列へ並べる順であり、読み直した位置とは限らない**——ホストが並べ替え得る。**実際の位置は `get_object` の `effects` が返す `position` である。**
- `effect.name=` が effect の名前。エフェクト一覧が返す名前をそのまま書く。
- 残りの行が `<項目名>=<値>` である。項目名は設定項目の名前そのものである。

## 書かなかったものはホストが埋める

**全項目を書く必要は無い。** 書かなかった設定項目は効果の既定値になり、**出力の効果は書かなくても付く。**

実測: `effect.name=図形` と `サイズ=100` の 2 行だけを持つ alias から、既定値で埋まった `図形` と、全項目が既定の `標準描画` を持つオブジェクトが生まれた。

したがって alias に書くのは**既定と違う項目だけ**でよい。既定が何かは `describe_effects` ではなく、1 つ作って `get_object` で読めば分かる。

**書かなかった項目の既定値が、書いた項目を無効にすることがある。** 実測: `図形` へ `角を丸くする=1` だけを書くと、読み直しは真を返すのに描画では丸くならない——書かなかった `ライン幅` に既定値 `4000` が入るためである。**`describe_effects` が返す `description` はこの関係を名指すことがある**（「ライン幅が大きいと反映されません」）。

**したがって既定値を読む理由は 2 つある**——書き足す項目を選ぶためと、**書いた項目が効く条件を満たしているかを確かめるため**である。

## 複数のオブジェクトを持つ形

1 つの alias は複数のオブジェクトを持てる。そのとき節の名前は `[Object]` ではなく 0 から始まる番号になり、各オブジェクトが `layer=` を持つ。

```
[0]
layer=0
frame=0,80
[0.0]
effect.name=テキスト
[1]
layer=1
frame=100,180
[1.0]
effect.name=図形
```

**`layer` も `frame` も絶対値ではなく、配置先を起点とする相対値である。** 実測: この alias をレイヤー 7・フレーム 500 へ配置すると、1 つ目はレイヤー 7 のフレーム 500-540 へ、2 つ目はレイヤー 8 のフレーム 600-640 へ生まれた。**どちらも配置先の値が加算されている。**

配置先を 1 つ指定すれば、残りはそこからの相対で決まる。時間差で現れる複数のオブジェクトを 1 呼び出しで組めるのはこのためである。

**宛先が 1 件でも埋まっていると、alias 全体が同じだけずれる。** ずれるのは絶対の位置であり、**相対の構造は保たれる。**

**これは失敗にならない。** ずれは `created` の各 selector にしか現れない。**`placement_adjusted` が真なら、`created` の全件を見る。**

## frame 行が区間を決める

```
frame=<開始>,<中間点…>,<終了>
```

中間点の位置はここに入る。`frame=0,40,80` なら中間点が 1 個あり、区間は 2 つになる。

## トラックバーの値と移動

```
<項目名>=<値0>,…,<値N>,<移動モード名>,<フラグ>[|<パラメータ0>,<パラメータ1>,…]
```

- **値の個数は `frame=` の要素数と一致する。** 中間点 2 個 → 3 区間 → 値 4 個である。
- `<移動モード名>` は AviUtl2 が持つ移動方法の名前である。
- `<フラグ>` は整数 1 個で、**bit0 加速 / bit1 減速 / bit2 中間点無視**である。実測: `,7` で作って読み直すと 3 つとも真に、`,4` では中間点無視だけが真になった。
- `<パラメータ>` は `|` の後ろにカンマ区切りで並ぶ。**`|` は節の開始を示す 1 文字であり、区切りではない**——`|` で 2 つ目を区切ると、そこから後ろが黙って捨てられる。実測: `ランダム移動,0|30` はパラメータ 30 として読み直され、`直線移動(時間制御),0|30|70` は `0|30` として保存された。後者は失敗も警告も返らない。**省略すると移動方法ごとの既定値が入る。**

移動を持たない項目は値 1 個だけを書き、移動モード名もフラグも付けない。**静的な値は区間の数に依らず 1 個である。**

### 時間制御はフラグではなく移動方法が持つ

時間制御を効かせるのは移動方法の名前である。実測: `直線移動(時間制御)` で作ると時間制御が真になった。**接尾辞を持たない名前でも真になるものがある**——時間制御は名前の綴りではなく、その移動方法の性質である。

**時間制御のパラメータは、ベジェ曲線の制御点である。** `|` の後ろに **1 制御点あたり 4 つ**の数値をカンマで並べる。

```
X=0.00,400.00,直線移動(時間制御),0|0,0,0.3,0,0.5,0.6,0.2,0,1,1,0.3,0
```

- 4 つは順に **`x`（時間位置）・`y`（値位置）・`vx`・`vy`（ハンドル）**である。**`0,0` が開始、`1,1` が終了を指す。**
- **ハンドルは制御点ごとに 1 つだけ綴る。** 出側が `点 + ハンドル`、入側が `点 - ハンドル` の鏡像になる。
- **制御点は時間位置の昇順に並べる。** 順を外した綴りは受理され、読み直しても書いたとおりに返るが、**評価がその位置で飛ぶ。** 失敗も警告も返らない。
- **両端を省いて 4 つだけ書ける。** `0|<vx0>,<vy0>,<vx1>,<vy1>` は、位置 `(0,0)` と `(1,1)` を補った 2 制御点と同じ曲線になる。

既製の綴りが 4 つある。**係数から起こす必要は無い。**

| 効き | パラメータ |
|---|---|
| 等速 | 省略する |
| 加速（ease-in） | `0.5,0,0,0` |
| 減速（ease-out） | `0,0,0.5,0` |
| 加減速（ease-in-out） | `0.5,0,0.5,0` |

**中間点の値は効かない**（[objects-and-effects.md](./objects-and-effects.md)）。**動いて止まる形——`[a,b,b,b]`——なら区間を持つオブジェクトでも使える。**

**bit3 は参照式が在ることを示す。** 立つと `|` の後ろが 2 節になり、前が参照式、後ろがパラメータになる。実測: `X=0.00,0.00,直線移動(時間制御),8|透明度`。パラメータを持つ移動方法では `ランダム移動,8|X*2|15` の形になる。

**式の無い bit3 は受け付けない。** `直線移動,8` も `直線移動,8|` も `create_object` が拒み、オブジェクトは 1 つも作られない。ホストは 1 つ目の節をパラメータとして読み、**その項目は 1 フレームも動かない。** **この守りは `alias_name` には掛からない**——登録済みエイリアスは一覧に載る名前が必ず作成できる側であり、その本文がその形を含んでいれば作成は通る。既に壊れている項目は読み取りが `unknown` の生文字列になり、移動情報も添えられない。

**bit4 も在り、ホストの UI が立てる。** 実測: `直線移動,16` は保存も評価も保たれた。読み取った行が持っていれば、落とさずそのまま書き戻す。

### 移動方法の名前は環境ごとに違う

**一覧をここへ写していない。** 移動方法はプラグインが足せるため、名前の集合は AviUtl2 の入っている環境ごとに違う。

引く経路は失敗の応答にある——`set_object_item` へ一覧に無い名前を渡すと、`details.known_movements` にその環境の移動方法が並ぶ。**この失敗は書き込みを発行しない。**

**`details.known_movements` がこの一覧を引く唯一の経路である。** `list_modules` は移動方法を返さない——同梱のスクリプトが一覧に現れないためであり、**`script_track` が 0 件でも移動方法は在る。**

**一覧に載る名前が全て書けるわけではない。** 要素は名前と、その名前で書けるかどうかを持つ——登録されていて名前としては正しいのに、書くと読み直しがその移動を失う名前が混じる。**件数も全件とは限らない**——上限を超えた分は切られる。

## 黙って捨てられる書き方がある

**末尾のフラグを欠いた行は、その行ごと黙って破棄されて既定値になる。** エラーも警告も返らない。実測: `Y=-100.00,0.00,100.00,直線移動`（フラグ無し）を含む alias は受理され、**その項目は `0.00` になった。** 同じ alias の正しい行だけが効いていた。**不正な移動モード名を含む alias は違う**——`object_alias` へ渡すと `create_object` が受け付けない。

alias が受理されたことは、書いた行が全て効いたことを意味しない。作った後は読み直して、書いたとおりになっているかを確かめる。

**移動パラメータの個数と意味は移動方法ごとに決まる。** 受け付けられない綴りも**書き込みは成功する。** その先は移動方法で分かれる——**時間制御の変種では書いたとおりに保存され、評価だけが既定へ倒れる。** 値域を外れた綴りも同じである。実測: `直線移動(時間制御)` へ 11 通りのパラメータを書いて、1 つも違わず直線であった。**それ以外の移動方法では、書いた値が保存されない**——既定値へ差し替わるか、パラメータごと落ちる。読み直せば分かる。

**並び順を外した場合は既定へ倒れず、評価が不連続になる**（時間制御の節）。

**時間制御の変種で外したことは読み直しでは分からない。** 確かめる経路は `get_effect_item_values` である。

**読み直しは 1 度で落ち着くとは限らない。** 実測: パラメータを省いた移動を持つオブジェクトは、作成直後の alias と、その次に読んだ alias が違った——ホストが既定のパラメータを書き足すためである。**編集を挟んでいなくても fingerprint が変わる**ため、作成直後の selector で編集すると `precondition_failed` になり得る。応答が添える現在の姿へ持ち替えればよい。

**この書き足しは既定パラメータを引く経路でもある。** パラメータを省いた行で 1 つ作って `get_object` を読めば、移動方法ごとの既定値が `track.params` と `value.params` に並ぶ。**トラックバー項目が多い効果を使えば、1 呼び出しで複数の移動方法を一度に引ける。** **時間制御の変種だけはこれで引けない**——既定が空であるため、制御点の綴りは出て来ない（綴りは時間制御の節が述べる）。

## テキストの値では `\` が 2 つの綴りを持つ

テキスト種別の設定項目の値では、`\n` が改行を、`\\` が `\` 1 つを表す。**それ以外の `\` を含む行は `object_alias` へ渡すと `create_object` が受け付けず、オブジェクトは 1 つも作られない。** 値の末尾に置いた単独の `\` も同じである。Windows のパスをテキストへ書くなら `C:\\temp\\note` と綴る。

**パス種別・選択肢種別の値は解かれない。** 実測: `ファイル=C:\temp\note.png` は書いた綴りのまま保存された。これらの項目には `\` をそのまま書く。

**この守りは `alias_name` には掛からない**——登録済みエイリアスは、本文が規則の外の `\` を含んでいても作成が通る。

## トラックバーグループ

`Group=1` / `Group2=1` / `Group3=1` の行は、`標準描画` の座標や回転のように**複数の項目が 1 組として扱われる**ことを表す。

**行は組の後ろに置かれ、直前の項目群を閉じる。** 実測: `X` `Y` `Z` の直後に `Group=1` が、中心の 3 項目の直後に `Group3=1` が、回転の 3 項目の直後に `Group2=1` が並び、`Group2=1` より後ろの項目はどの組にも属していなかった。

**書かなくてよい。** 実測: これらの行を 1 つも持たない alias で作っても、読み直すと同じ位置に並んで返り、項目の所属も変わらなかった。組を決めているのは効果の側であり、alias の行ではない。
